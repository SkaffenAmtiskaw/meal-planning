# Purpose
The date picker is implemented independently in two different places in the current app (the calendar header and the add meal modal). A third is planned in a future story. If the implementation is not unified these components will drift over time. This story serves to provide a unified experience whenever a user needs a date.

The work was split into four stories on 2026-09-25, because it held several pieces that ship and can be checked on their own: date setup, the today markers across the calendar views, the header picker and the meal form picker. The design stays here in one copy, and each story embeds the sections it builds.

## One panel, three placements
The component is only the panel. Each placement supplies its own trigger and decides what happens
on pick.

| # | Placement | Trigger | On pick | Status |
|---|---|---|---|---|
| 1 | Header — jump to date | Date field in the toolbar | Navigates the calendar to that date | **This change** |
| 2 | Add / Edit meal — date field | The form's Date field | Sets the field and closes | **This change** |
| 3 | Meal detail — Move / Duplicate | "Move to…" / "Duplicate…" buttons | The modal moves / copies the meal, closes, shows its own Undo | **Planned, not yet implemented** |

- The header has no Today footer, because the toolbar already has a Today button.
- In the meal form, the dots help you avoid planning two dinners by accident.
- In Move / Duplicate, the picker only reports the date that was picked. The meal detail modal
  owns the move or copy, closing, and Undo.

## Anatomy: fixed vs. optional

| # | Part | | Notes |
|---|---|---|---|
| 1 | Label | Optional | Small uppercase line saying what the pick does ("Move to"). Leave it out when the trigger already says so. |
| 2 | Shortcuts | Optional | Two cards, each showing its target date. `relative` uses the Tomorrow / Next day rule (below) and hides any that land in the past. Can be replaced with a custom list. |
| 3 | Month nav | Always | Previous / next month, with the month and year between them. |
| 4 | Weekday row | Always | Always starts on **Sunday**. This is set once for the whole app, not per picker. |
| 5 | Day grid | Always | A fixed 6-week grid with today, selected, outside-month, and optional meal-dot states. |
| 6 | Hint | Optional | One line of help text below the grid. |
| 7 | Today footer | Optional | A quick "Today" pick, for placements that don't have one nearby. |

^anatomy-parts

### Day cell states
Two separate marks that can stack:

| State | Treatment |
|---|---|
| Default | Navy number |
| Outside month | Muted number (`navy.3`), still selectable |
| Has meals | Small **forest** dot under the number |
| Today | **Navy outline ring** around the number, bold |
| Selected | **Soft sage circle** behind the number (`sage` at 45% opacity), navy bold text (~11:1) |
| Selected + today | The sage circle sits inside the navy ring |

Ember (orange) is kept for actions only. It is no longer used to mark days.

### Shortcut labels (`shortcuts="relative"`)
- Meal on **today**: *Tomorrow* / *Next week*.
- Meal on **any other day**: *Next day* / *Week later* (relative to that meal's date).
- Meal in the **past**: a shortcut only shows if it lands on today or later. If neither does, you
  just get the calendar.

^shortcut-labels

### Behavior (all placements)
- Always 6 rows, so paging through months never changes the panel's height.
- Days from neighboring months can be picked; picking one moves the view to that month.
- Past dates stay selectable everywhere. The calendar can be kept as an honest record.
- Keyboard: arrows move by day or week, PgUp/PgDn by month, Home/End to week start or end, Enter
  picks, Esc closes.
- Opens anchored to its trigger and flips above if there's no room below. On mobile it becomes a
  bottom sheet with the same parts.
- Days that already have meals **stack**: moving or duplicating onto an occupied day adds the meal
  alongside the others. No swapping, no title matching. (Relevant to the planned Move /
  Duplicate.)

## Mantine Boundary

The repo already has `@mantine/dates` 9.0.0 installed. We add a thin wrapper,
`CalendarDatePicker`, around Mantine's `DatePicker` and don't rebuild the calendar itself.

**Mantine owns** (`<DatePicker>` · `<DatesProvider>`)
- The month grid, days from neighboring months, and the fixed 6-week layout.
- Month navigation, plus the month / year views you get by clicking the title.
- Keyboard support, focus handling and aria labels.
- Sunday week start: set `firstDayOfWeek: 0` once in `<DatesProvider>` at the app root. That
  covers every picker.
- Hooks for styling the day cells and adding the meal dots.

**`CalendarDatePicker` owns** (`src/_components/CalendarDatePicker`)
- Built from Mantine parts: the label, the two shortcut cards, the hint line and the Today button,
  stacked around the Mantine picker.
- The Tomorrow / Next day labels, and hiding shortcuts that would land in the past.
- Day-cell styling through a CSS module: navy outline ring for today, sage circle for selected,
  a forest dot for days with meals. Colors come from theme tokens.
- Reports the picked date and nothing else. It doesn't close itself, show toasts, or change any
  data.

**Each consumer owns** (CalendarHeader · MealForm · MealDetail)
- The trigger, and the popover (desktop) or drawer (mobile) that holds the picker.
- Whether it's open, and closing it after a pick.
- What a pick does: navigate, set the field, or move / copy the meal.
- The Undo toast and any error handling (Meal Detail only).
- Looking up which days have meals, from whatever calendar data it already has loaded.

**Deliberately not using**
- **`DatePickerInput`.** Its dropdown can't hold our label, shortcuts or hint. The header will
  switch to a button that looks like an input and opens the same popover.
- **The `presets` prop.** It shows presets as a side list, with no target date under each label
  and no way to hide the ones that land in the past. The two shortcut cards cover it.
- **`minDate` / `excludeDate`.** Past dates stay selectable on purpose.

## Recommended Configuration

| Prop              | Type                   | Default     | 1 · Header              | 2 · Meal form       | 3 · Move / Dup *(planned)*   |
| ----------------- | ---------------------- | ----------- | ----------------------- | ------------------- | ---------------------------- |
| `value`           | ISO date \| null       | —           | Date in view            | Field value         | Meal's date                  |
| `onChange`        | `(iso) => void`        | —           | Consumer navigates      | Consumer sets field | Consumer moves / copies      |
| `today`           | ISO date               | local today | —                       | —                   | —                            |
| `label`           | string                 | none        | —                       | —                   | "Move to" / "Duplicate to"   |
| `shortcuts`       | `'none' \| 'relative'` | `'none'`    | none                    | none                | relative                     |
| `shortcutItems`   | `{label, date}[]`      | —           | —                       | —                   | — (override, if ever needed) |
| `markedDates`     | ISO[]                  | `[]`        | Days with meals         | Days with meals     | Days with meals              |
| `hint`            | string                 | none        | —                       | —                   | Stacking note                |
| `showTodayButton` | boolean                | `false`     | false (toolbar has one) | true                | false                        |


Not configurable: colors, cell size, the 6-row grid, month navigation, the Sunday week start, past
dates being selectable, and the Tomorrow / Next day labeling rule. Keeping these fixed is what
makes the pickers consistent.

## Phones: Bottom Sheet
![Phone bottom sheet](datepicker_mobile.png)

On phones, every placement opens the picker in a **bottom sheet** instead of a popover. The
sheet is not full screen: at touch size the picker is about 600px tall, and the sheet keeps the
page visible behind it. It sits within thumb reach and closes with a swipe down or a tap on the
backdrop. The sheet belongs to the consumer (Mantine `Drawer`, bottom), the same as the popover
on desktop.

- **Touch size (`variant="sheet"`).** Day cells about 50px (at least 44px), month arrows 44px,
  17px day numbers, larger dots and shortcut cards. The parts and rules stay the same.
- **Title moves to the sheet header.** The placement's label ("Move to") becomes the sheet's
  title, with a Close button; the picker's own `label` isn't used.
- **Swipe between months.** Swiping left or right on the grid pages months, alongside the arrows.
- **Jump by month.** Tapping the month title opens a month / year list.
- **Tapping a day is final.** It picks and closes, with no Done button, same as desktop.
- **No keyboard.** On phones the meal form's Date field opens the sheet, so the on-screen
  keyboard never appears.
- **Pressed states, not hover.** A day tints when pressed.
- **Safe area.** The sheet clears the home indicator, and its content scrolls if it's ever taller
  than 90% of the screen.

## Aligning every today / selected indicator

Target everywhere: **today = navy outline ring**, **selected = soft sage circle**, and they stack.
The selected date is only marked where you pick a date: the date picker and the mobile month grid.
Everywhere else, only today is marked.

| Place | Today (now) | Plan |
|---|---|---|
| Month view (desktop) | Filled orange circle on the day number. The selected date isn't shown. | Navy ring on today. The selected date stays unmarked. |
| Month view (mobile) | Filled orange circle. Selected day gets a tinted cell: orange tint if it's today, grey otherwise. | Navy ring for today, sage circle for selected, no cell tint. Same look as the picker, just larger. |
| Mobile month agenda heading | "Today · Thursday, September 10" text prefix | No change. |
| Week view | Filled orange pill around "Wed 9/18" | Navy outline pill around the whole label, with navy text. The selected date stays unmarked. |
| List view (desktop) | Filled orange circle on the day number, plus an orange-tinted row | Navy ring on the day number; drop the row tint. The date you jump to isn't marked; scrolling there is enough. |
| List view (mobile) | Orange day label, plus an orange-tinted section | 🚛 Moved to [[Mobile List View#Design Update - Today Marker]]. Phones show a "Coming soon" placeholder today; that story builds the mobile list. |
| Header date picker (desktop + mobile) | Mantine default: filled blue selected day, bold today | Swap in the shared date picker. |
| Add / Edit meal date field | Browser's native date picker (looks different on every OS) | Swap in the shared date picker, with the Today button. |
| Meal detail — Move / Duplicate | — | *Planned, not yet implemented.* Will use the shared picker. |
