# Purpose
The meal detail modal styling is bare-bones and does not match the rest of the calendar. It also needs to easily allow a user to edit a meal.

The modal also needs to be updated to follow current project coding conventions. It refers to "meal events" which do not follow the new naming convention of not using the word "event" (because these even though we use a calendar, they aren't really events). It also needs to use the `CalendarModalContext` like the "add meal" modal currently does.

# Design Handoff

A redesign of the desktop meal detail modal (the one that opens when you click a meal on the
calendar). It now matches the rest of the app: the same header, footer and dish markers as Add
Meal. Notes can be edited in place, there are Move to / Duplicate actions, and there's a full edit
mode that reuses the Add Meal layout.

> **Build Order: Implement this AFTER the [[Unified Date Picker Component|unified date picker]]**.
> Move to, Duplicate and the edit-mode Date field all use that picker. Nothing here should be built with a temporary or native date input.

![Read view](assets/meal-detail-modal/01-read-view.png)

## Read view
What you see when you open a meal.

**Header**
- A small square in the meal's color, then the date in long form ("Thursday, September 24").
- Meal name as the title (20px, bold).
- The description underneath, if there is one. No description → nothing rendered.
- Close button top right.

**Dishes**
- Section heading "DISHES" with the count ("4 dishes").
- Each dish is one row: a marker, the name, a source line, and the note.
  - **Marker:** filled green dot = saved recipe; hollow green ring = reference (URL, or book and
    page); light grey dot = no source. The same marks as the Add Meal chips.
  - **Name:** green and linked when there's a source; plain navy when there isn't.
  - **Source line:** after the name, in small italic. "Saved recipe" for a saved one, or the
    reference text itself.
  - **Note:** its own line in full navy, never truncated, author line breaks kept. Same rules as
    the list-view dish notes handoff. No note → nothing rendered.
- Rows are evenly spaced, whether or not they're linked. (The current modal spaces linked and
  plain dishes differently.)

**Footer action bar**
- Left: **Move to…** and **Duplicate…** (quiet green text buttons).
- Right: **Edit meal**, an *outlined secondary* button with a pencil icon, deliberately not
  orange. Nothing has changed yet, so it shouldn't look like a submit button. Orange is only
  used when committing a change (Save note, Save changes).

## Inline note editing
![Inline note edit](assets/meal-detail-modal/04-inline-note-edit.png)

Each dish row has a small button on the right: **Edit note** (solid outline) if it has a note,
**Add note** (dashed outline) if it doesn't.

- Clicking it swaps the note line for a textarea with **Cancel** and **Save note** (orange).
- Only one dish is edited at a time; opening another closes the first.
- Saving updates the row immediately. Saving an empty note removes the note line.
- Only notes can be edited here. Name and source changes go through Edit meal.

## Move to / Duplicate
![Move to picker](assets/meal-detail-modal/02-move-to-picker.png)

Both buttons open the **unified date picker** as a popover above the action bar, set up for this
placement:

- Label: "Move to" or "Duplicate to".
- Relative shortcuts, labeled from the meal's date:
  - The meal is **today**: *Tomorrow* / *Next week*.
  - The meal is on **any other day**: *Next day* / *Week later*.
  - The meal is **in the past**: a shortcut only shows if it lands on today or later; if neither
    does, you just get the calendar.
- Dots on days that already have meals, with the hint "Dots mark days that already have meals —
  this one will be added alongside them."
- Past dates stay selectable.
- The button that opened the picker stays highlighted while it's open. Clicking it again closes
  the picker.

**Picking a date acts immediately.** There's no confirm step.

![Moved, with Undo](assets/meal-detail-modal/03-moved-with-undo.png)

- **Move:** the meal moves, the picker closes, and the modal stays open showing the new date. A
  confirmation bar appears above the footer, "Moved to Friday, September 25.", with **Undo**.
  Undo puts the meal back on its original date.
- **Duplicate:** a copy is made on the picked date. The modal stays on the original meal and
  shows "Copied to …".
- Picking the meal's own date in Move to just closes the picker.
- **Occupied days stack.** Moving or duplicating onto a day that already has meals adds this one
  alongside them. No swapping and no title matching; the user tidies up any duplicates.
- Undo and the confirmation bar belong to this modal, not to the date picker.

## Edit mode
![Edit mode](assets/meal-detail-modal/05-edit-mode.png)

**Edit meal** turns the same modal into the **Add Meal layout** (see
`design_handoff_add_meal`). There's one form for adding and editing; follow that handoff for
the form itself.

Differences from Add Meal:
- Title "Edit Meal", with the meal's date underneath.
- Fields are pre-filled with the meal and its dishes.
- The Date field uses the unified date picker (meal-form placement: meal dots, Today button).
- Footer: **Delete meal** (red text) on the left; **Cancel** and **Save changes** on the right.

![Unsaved changes](assets/meal-detail-modal/06-edit-unsaved-changes.png)

- **Save changes** stays muted (light orange) until something changes, then turns full orange.
  An "Unsaved changes" marker (small orange dot + text) appears beside Cancel.
- **Save** returns to the read view with the updates and a "Changes saved." confirmation bar.
  Dishes left with an empty name are dropped.
- **Cancel** or **Close** with no changes → straight back to the read view.
- **Cancel** or **Close** with unsaved changes → ask "Discard your changes to this meal?" before
  leaving.

### Delete
![Delete confirmation](assets/meal-detail-modal/07-delete-confirm.png)

Clicking **Delete meal** replaces the footer with a red confirmation bar: "Delete **Dinner -
Meatless** and its 3 dishes? This can't be undone.", with **Keep meal** and **Delete meal**
(solid red). No second modal on top. Deleting closes the modal.
