# Purpose
User feedback noticed it was difficult to understand how to add a meal with saved dishes. The design has been updated to allow users to better discover saved recipes.

## Meta-Instructions
The design handoff below is generated by Claude Design. It has been reviewed and approved by the user, but it is very detailed and the user may forget details in it (or she might change her mind). If there is a conflict between the design handoff and the user's instructions, you should prompt the user for clarification.

The design handoff should be treated as a source of truth (except in the case of user conflict) for the UX/UI. It should not be a source of truth for implementation details. Mantine boundaries are a best guess not a binding contract. Clean architecture and component design are more important than trying to preserve the design handoff's approach.

# Design Handoff

Follow-up to [[Add Meal UX Changes]]. The two-pane modal, collapsible dish row and mobile sheet from that handoff stay. This one changes **how a dish gets its saved recipe**, and adds a tag filter.

## What's wrong today
A mobile tester couldn't find how to add a saved recipe. The path is *Add source → Saved →
picker*: three taps deep, behind a chip labelled for how we store the data rather than what
people are trying to do. When shown where it was, they said they'd never have looked there.

People think "add the curry I saved", not "add a dish, then give it a source". Saved recipes need
to be the first thing you see when adding a dish, not an option buried inside it.

## The change
- **Desktop:** a third column, **Saved recipes**, is always on screen next to the dishes. You can
  browse, search and filter it by tag, and add a recipe as a dish in one click.
- **Mobile:** no room for a column, so the dish name field doubles as a search. **Add dish** adds a
  row with your saved recipes already listed under it.
- **Both:** the source picker (None / Saved / Reference) is gone. A dish has a saved recipe, a
  reference, or nothing, and the row shows which.

## 2. Dish row (both)

`[ name ] [ recipe chip ] [ note chip ] [ expand arrow ] [ delete ]`
(Mobile puts the name and delete on one line, and the chips and arrow on the line below.)

### Recipe chip
| State | Look | Tap |
|---|---|---|
| Empty | Dashed outline, grey hollow ring, **"Link recipe"** | Starts linking (desktop: link mode, §3; mobile: opens the saved list, §4) |
| Saved recipe | Solid outline, **filled green dot**, recipe name | Opens/closes the expand panel |
| Reference | Solid outline, **hollow green ring**, URL or book text | Opens/closes the expand panel |

A long label drops `https://`, stays on one line with an ellipsis, and shows in full on hover.
The chip never wraps.

### Note chip
Dashed **"Add note"** when empty, solid **"Note"** when set. Tapping it opens or closes the expand
panel. While the row is closed, the note shows as a line under it (one line with an ellipsis on
desktop, wraps on mobile).

### Expand arrow
Opens and closes the panel. Points down when closed, up when open. Several rows can be open at
once.

### Delete
Trash icon. Uses the app's **existing delete confirmation modal**, and the row is removed once
confirmed. Hidden when only one dish is left.

### Expand panel
![Desktop Expanded Rows All Tags](assets/calendar-add-meal/03-desktop-expanded-rows-all-tags.png)
![Mobile Row Expanded](assets/calendar-add-meal/06-mobile-row-expanded.png)
Desktop: two columns (Recipe | Note). Mobile: stacked.

- **RECIPE**, with a saved recipe linked: the recipe name (wraps, never cut off), then text
  actions **Change** (starts linking again) and **Remove** (unlinks; the row keeps its name).
- **RECIPE**, with nothing linked: a filled green button **"Link a saved recipe"**, then the helper
  "or add a reference", then a text field (placeholder "URL, or book and page").
- A dish has **either** a saved recipe **or** a reference. Linking a saved recipe clears the
  reference.
- **NOTE:** a textarea (placeholder "Prep reminders, swaps, what to buy…").

## 3. Saved recipes column (desktop)

### What's in it
Every recipe and bookmark in the planner, the same set as the Recipes page. Each result shows
the name, its kind in muted text (**Recipe** / **Bookmark**), its tags as small colored badges,
and an action button on the right.

### Order
**Most recently used on a meal first**, then alphabetical. See *Data change* below.

### Search
Matches anywhere in the name, ignoring case. Works together with the tag filter (a result must
match both). If nothing matches: "No saved recipes match."

### Browse mode (default)
![Desktop Layout](assets/calendar-add-meal/01-desktop-browse.png)
- **Add** (outlined pill) adds a new dish at the end of the list, named after the recipe and
  already linked to it.
- **A recipe can be on a meal only once.** Recipes already on this meal show a muted
  **"Added"** that does nothing.

### Link mode
![Desktop Linking](assets/calendar-add-meal/02-desktop-linking.png)
Starts from an empty **Link recipe** chip, **Change**, or the panel's **Link a saved recipe**.

- The dish being linked gets a light green tint and green border.
- A banner at the top of the column reads **"Linking to *Dish name*"** with **Cancel**.
- The search is **prefilled with the dish's name** and **any selected tags are cleared**, so an
  old filter doesn't hide the likely match.
- Every action button becomes a filled green **Link**. Recipes already on the meal still show
  "Added".
- Picking one links it to that dish, **keeps the dish's name** (or uses the recipe's name if the
  dish is unnamed), leaves link mode and clears the search.
- **Cancel** or **Esc** leaves without changing anything. Deleting the dish being linked also
  leaves link mode.

- The list reopens when the name field is tapped, or from an empty Link recipe chip, **Change**, or
  **Link a saved recipe**. Only one row's list is open at a time.
- Tag chips sit in a single row that scrolls sideways.

## 5. Tag filter (both)

Shown above the results: the library column on desktop (wraps), the search list on mobile
(scrolls sideways).

- **Selected tags must all match.** A recipe has to carry every selected tag to show.
- **Selected tags come first**, filled with the tag's own color from the planner palette. Tap to
  turn one off. **"Clear"** appears when any are selected.
- **Only tags that would return something are shown**: tags carried by at least one of the
  current results (search + selected tags). Tags that would return nothing are hidden, not
  greyed out.
- **Most used first.** Unselected tags are ordered by how many *current results* carry them;
  ties go to whichever is used more across the whole planner. That count shows in muted text
  after the name and updates as you narrow.
- **Six shown at a time**, selected ones included. The rest sit behind a dashed **"+N more"** that
  shows them all and turns into **"Fewer"**.
- Picking a tag moves the keyboard highlight back to the first result.

---

## 6. Keyboard (desktop)

In the library search field:

| Key | Does |
|---|---|
| ↓ / ↑ | Moves a highlight through results (white background, thin green outline) |
| Enter | Runs the highlighted result's action: **Add**, or **Link** in link mode |
| Esc | Clears the search and highlight; in link mode, also leaves link mode |

- The highlight moves back to the first result whenever the search or tags change. Hovering with
  the mouse moves the same highlight, so the mouse and keys never point at two different rows.
- Every result can be reached with Tab; **Enter** or **Space** runs its action. "Added" results
  can be focused but do nothing.
- A one-line hint under the tags shows the keys: **"↑↓ move · ↵ add · Esc clear search"**, or
  **"↑↓ move · ↵ link · Esc cancel linking"** in link mode.
- Tab order: meal fields → each dish row (name, recipe chip, note chip, arrow, delete, then panel
  fields) → Add dish → library search → tags → results → Cancel → Add Meal.

---

## 7. Saving
- Date and Meal name are required. **Add Meal** stays disabled until both are filled.
- Dishes with no name are dropped on save and don't count toward "N dishes on this meal".
- Saving a meal updates **last used** on every saved recipe it links (see below).

## Styling
Same palette and tokens as the previous handoff. The new bits:

- **Saved recipes column:** chalk tint (same as the Meal column), divider on its left. Section
  label "SAVED RECIPES" is small, bold, uppercase, spaced out, muted navy.
- **Link-mode banner:** light forest background with a forest border, navy text with the dish name
  in bold, forest **Cancel** text button.
- **Linking dish:** forest border with a very light green fill.
- **Action pills:** *Add* is white with a light forest border and forest text; *Link* is filled
  forest with white text; *Added* is muted grey with no border.
- **Tag chips:** pill-shaped. Unselected: white, light border, a small dot in the tag's color,
  the name in navy, the count muted. Selected: filled with the tag's background, border and text
  colors from the tag palette, no count. "+N more"/"Fewer" is a dashed forest pill.
- **Tag badges on results:** smaller pills with the tag's background and text colors, no border.
- **Filled dot = saved recipe, hollow ring = reference, grey ring = nothing linked.** Same meaning
  on chips, results and the panel. Don't add the words "(recipe)"/"(bookmark)" to chips; the result
  list already shows the kind.
- Contrast rule from the last handoff still applies: interactive labels, counts beside tags, helper
  lines and the key hint all need 4.5:1 or better.

## Likely Mantine boundaries
Starting points only. Use whatever fits the codebase best.
- Modal (desktop) / full-screen modal (mobile), with a grid for the three columns
- `TextInput` with a search icon for library search; `ScrollArea` for the independent scroll areas
- Chip or Badge for tag filter chips, reusing the existing `Tag` component for result badges
- Button (outline / filled / subtle) for Add, Link, Added
- Combobox, or the existing search-as-you-type pattern, for the mobile name field
- Collapse for the expand panel; ActionIcon for the arrow and delete

## ⚠️ Data change — required
**Saved recipes and bookmarks need a new "last used" date.** Set it whenever a recipe or bookmark is linked to a dish on a saved meal. It drives the "Recently used" order in the library and the mobile search list. Recipes that have never been used sort after used ones, alphabetically.

Nothing else in the data changes: dishes still store a name, an optional saved recipe or
reference, and an optional note.

# Suggested Approach

## Enumerated behaviors

1. **Open the Add Meal modal** from the calendar header or a list-view date; system renders it as a large dialog on desktop and a full-screen sheet on mobile.
2. **Render the desktop modal layout** with three columns: Meal (fixed, tinted, does not scroll), Dishes (scrolls independently), and Saved recipes (scrolls independently). Header and footer stay pinned. Mobile renders a single scrolling column.
3. **Display and edit meal fields** (Date, Meal name, Description); system validates that Date and Meal name are filled and disables the Add Meal button until both are.
4. **Add a dish** via the Dishes header "Add dish" button or the dashed "Add another dish" row. On desktop the system appends an empty dish row. On mobile the system appends an empty dish row and immediately opens that row's saved-recipe search list.
5. **Remove a dish** via the trash icon; system shows the existing delete confirmation modal, removes the row on confirm, hides the remove button when only one dish remains, and cancels any active link-mode / mobile search for that dish.
6. **Display a collapsed dish row** containing name, recipe chip, note chip, expand arrow, and optional remove button. The recipe chip reads "Link recipe" when empty, shows the saved recipe name with a filled green dot when linked, or shows the stripped/truncated reference with a hollow green ring when a reference is set.
7. **Expand/collapse a dish row** by clicking the recipe chip, note chip, or expand arrow; system reveals the expand panel, preserves all typed values, and allows multiple rows to be open at once.
8. **Link a saved recipe to an existing dish on desktop.** The user triggers link mode from an empty "Link recipe" chip, the expand panel's "Change", or the panel's "Link a saved recipe" button. System highlights the target dish, shows a "Linking to *Dish name*" banner, prefills the saved-recipes search with the dish name, clears selected tags, and switches each result's action to "Link". Selecting a recipe links it to the dish, keeps the dish name (or uses the recipe name if the dish is unnamed), exits link mode, and clears the search. Cancel, Esc, or deleting the linking dish exits link mode without changing anything.
9. **Add a saved recipe as a new dish on desktop.** The user browses/search/filters the saved-recipes column and clicks a result's "Add" button. System appends a new dish named after and linked to that recipe. Recipes already on the meal show a muted "Added" button that does nothing.
10. **Unlink a saved recipe** from a dish by clicking "Remove" in the expand panel; system keeps the dish name and clears the saved-recipe link.
11. **Add or edit a reference** for a dish. When no saved recipe is linked, the expand panel shows a reference field. System displays the entered URL/book text on the recipe chip with protocol stripped and truncated to one line. Linking a saved recipe clears the reference.
12. **Add or edit a note** for a dish. System shows an "Add note" chip when empty and a "Note" chip when set, displays the note text truncated below the closed row, and persists the note across source changes and expand/collapse.
13. **Search saved recipes by name.** System filters by case-insensitive substring and combines the search with selected tags. When nothing matches, system shows "No saved recipes match."
14. **Filter saved recipes by tags.** System lets the user select multiple tags with AND logic (a recipe must carry every selected tag). Selected tags are shown first, filled with their tag color, and can be tapped to turn off. Only tags carried by at least one current result are shown. Unselected tags are sorted by how many current results carry them, with ties broken by planner-wide usage count, and each shows that count. Only six tags are shown at a time; the rest hide behind a "+N more" chip that expands to show all and becomes "Fewer". A "Clear" button appears when any tags are selected.
15. **Use mobile search-as-you-type.** Adding a dish opens the saved list titled "RECENTLY USED" (top 5). The dish name field's placeholder reads "Dish name or search saved recipes". Typing filters the list and re-titles it "FROM YOUR SAVED RECIPES" (or "SAVED · TAG1 + TAG2" when tags are selected). Each result shows a "Use" button; tapping it fills the dish name, links the recipe, and closes the list. The last row reads "Add '*typed text*' as a new dish" and keeps the typed text. Before typing it reads "Type a name for a new dish" and does nothing. Editing the name of a linked dish unlinks it. The list reopens from the name field, an empty "Link recipe" chip, "Change", or "Link a saved recipe". Only one row's list is open at a time. Tag chips scroll sideways in a single row.
16. **Navigate the desktop saved-recipes list by keyboard.** System maintains a single highlight across results that moves with ↓/↑ and the mouse, activates with Enter, clears with Esc (and exits link mode), and shows the appropriate key hint under the tags.
17. **Submit the meal.** System validates required fields, drops unnamed dishes, calls `addMeal`, updates a `lastUsed` date on every linked saved recipe/bookmark, closes the modal and refreshes the calendar on success, or shows an error alert on failure.
18. **Cancel or close the modal** without saving; system discards unsaved changes and closes.

### Client/server and shape notes

- All UI/interaction pieces are **client** (event handlers, `useState`, browser keyboard). The only server pieces are the existing `addMeal` action and the schema/type changes for `lastUsed`.
- `SavedRecipesColumn` and `MobileSavedRecipeSearch` both depend on the same shared pieces: `useSavedRecipeSearch`, `useTagFilter`, `TagFilter`, `SavedRecipeResults`, `SavedRecipeResultItem`, and `useSavedRecipeKeyboard`. Extracting these first avoids duplicating search/filter/tag logic across desktop and mobile.
- `useSavedRecipeSearch` is a hook (no markup). `useTagFilter` is a hook (no markup). `useSavedRecipeKeyboard` is a hook (no markup). `useLinkMode` is a hook (no markup).
- `TagFilter`, `SavedRecipeResults`, `SavedRecipeResultItem`, `LinkModeBanner`, `MobileSavedRecipeSearch`, and `SavedRecipesColumn` are components (they produce markup).
- `usePlannerSavedItems` currently returns only `_id`, `name`, and `url`. It must be **reworked** (or replaced by a richer hook) to also return `kind` (`recipe`/`bookmark`), `tags` (resolved to tag objects), and `lastUsed`.
