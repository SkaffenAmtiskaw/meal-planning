# Purpose
The Add/Edit Meal Date field uses the browser's native date input, which looks different on every OS and doesn't show which days already have meals. This story switches it to the shared date picker, with meal dots so you don't plan two dinners by accident, and a Today footer. The modal subtitle shows only the chosen date. Edit mode in [[Meal Detail Modal & Edit Meals]] reuses this field.

## Behaviors
**Picker panel (every placement)**
9. When the Today footer is on, it shows today's date, and clicking it picks today.

**Desktop and phone containers**

13. *(part)* On phones the meal form's picker opens in the bottom sheet built by [[Header Date Picker]], titled **"Choose day"**.

**Add/Edit Meal placement**

18. The required Date field becomes an input-styled trigger showing "Thursday, September 24".
    - It keeps its current default date and its "Date is required" error.
    - **The picker:** marks the field value as selected, shows meal dots and has the Today footer.
19. Picking a date, or Today, sets the field and closes the picker. On phones no on-screen keyboard appears.
20. The modal subtitle shows only the date ("Thursday, September 24") and follows each pick. The meal name no longer appears in it. *(Corrected 2026-09-25: the subtitle already followed edits; it wasn't set only once. Sarah chose date only.)*

**Read-only users**

28. Viewers use the header picker like everyone else, and nothing behaves differently for them. They never see the meal form.

The modal formats the date with the named style from row 12, so the subtitle follows each pick. |
