# Notes
Sarah, 2026-11-01: "I'm starting goals with sort of nebulous ideas of 'we need to rework this page' but it's not broken down into stories yet. I want to think through the feature workflow for places where I first want to investigate my options, decide which of them are worth doing, decide on the UX for it, and then drill down into more granular stories." She also noted that for an area like recipes, she'll have made a few scattered notes before the goal starts, and they aren't comprehensive and many overlap.

**The flow Sarah approved 2026-11-01.** It's only for work that starts as an area. A clearly defined feature still goes through `/shape`, `/design-feature` and `/place-design`. It starts after the goal exists, because "is this in this release?" needs a release to compare against.

Once per goal:
1. **Gather and section:** sort the scattered notes and Roadmap lines into sections, merging overlaps and keeping her wording. A small area can be just one section. She expects this to be needed only sometimes.

For each section:
2. **Find options:** brainstorm and research what could be done, then a quick first pass sorts them into yes, no and needs thought, so the list doesn't turn into a research session per option.
3. **Decide:** only the options that need thought become open decisions. `/decide` already spreads them over as many runs as she wants, and decides whether each is worth doing and whether it's in this release.
4. **Design:** one or more `/design-feature` sessions, since a section can be too big for one.
5. **Split into stories:** `/place-design` cuts the design into stories, which go on to `/assess`.

**Sections are hubs,** since a hub is already the home for design and decisions several stories share. The goal groups them, so hubs don't nest. "Section" is a working name.

**It also has to clean up a goal that's messy and outdated,** which Sarah asked for 2026-11-01, naming [[Calendar Page]] as the example. Gather and section does this as part of its own job: it also finds lines and notes that are already done, out of date or duplicated, and Sarah decides what happens to each. Stories already in progress are sorted into sections, not explored again, so a section takes steps 2 to 5 only for the parts that still need them. `/check-drift` still checks an individual story's details against the code.

**What it reaches, at least:**
- `/roadmap`'s Gaps step, which makes one idea note per uncovered Done When item. An item that's a whole area starts this flow instead.
- `/design-feature`, which should take a section's hub as well as a feature note.
- The rule that a hub has a Roadmap line only while it has open decisions, since a section's line has to stay until it's split into stories.
- `/shape`, `/decide` and Note Conventions' Hub type and Next Step table.

**Where it would be used first:** [[Recipes Page]], whose sections might be recipe list, recipe detail, adding and updating recipes, and possibly bookmarks. [[Recipes Page Redesign]] and [[Recipes Page Wish List Research]] would merge into this work, and [[Filtering Recipe List]] would sit under the recipe list section and keep its decisions. [[Grocery List Creation]] could work the same way. Both goals' Done When name a research story that this flow would replace.
