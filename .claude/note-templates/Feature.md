# Design Handoff

## Meta-Instructions
The design handoff below describes a design the user reviewed and approved. Where a section names an artboard, the artboard is the design, and its sample data only illustrates it. The design is very detailed and the user may forget details in it (or she might change her mind). If there is a conflict between the design handoff and the user's instructions, you should prompt the user for clarification.

The design handoff should be treated as a source of truth (except in the case of user conflict) for the UX/UI. It should not be a source of truth for implementation details. Mantine boundaries are a best guess, not a binding contract. Clean architecture and component design are more important than trying to preserve the design handoff's approach.
