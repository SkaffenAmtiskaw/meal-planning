# Checking the Goals
If the user has already named the goals, such as by placing the line under a goal's heading or giving it 🎯 links, go on to placing the line.

Otherwise, read the notes in `notes/goals/`. If a goal's Roadmap Instructions say the work belongs to it, it does. Another goal fits when a line in its Purpose, Done When or What Belongs Here could include the work, and dev tooling also fits a goal it would make easier. If none fits, don't ask. Otherwise, ask the user which ones the work serves, naming each goal that fits and quoting that line. Don't recommend one for tooling, because whether tooling joins a ranked goal is the user's priority call.

An item serves one goal, or two only when neither can be done without it. Offer an item the building or planning goal only when that goal can't be done without it, because linking it there schedules it now.

# Placing a Story's Line
If the line is in Ideas or Unaffiliated, move it as the Roadmap's "How this file works" describes under Later. A line already under a goal's heading, or in Now or Next, stays where it is. It goes into Next or Planning only if the user says so.

# Linking a Collecting-Note Item
End the item with a 🎯 link for each of its goals. If one is the building goal, move the item into the note's open kicked-off copy for that goal (`<note> YYYY-MM-DD`), or if there's none, kick one off as `/kickoff`'s "Kicking off for the building goal" describes. If the copy's line is in Later, ask whether it moves into Next.
